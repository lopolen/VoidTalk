# Антиспам постів

Антиспам система застосовується тільки під час створення поста:

```http
POST /api/v1/posts
```

Усі ліміти прив'язані до `current_user.id`. Система не використовує IP-адреси,
device fingerprint, cookies поза звичайною auth-сесією або спроби визначати,
скільки акаунтів належать одній реальній особі.

## Правила

- Мінімальна довжина поста після `trim`: 3 символи.
- Максимальна довжина поста після `trim`: 1000 символів.
- Cooldown: 30 секунд між постами одного користувача.
- Не більше 10 постів за останні 10 хвилин для одного користувача.
- Не більше 50 постів за останні 24 години для одного користувача.
- Пост відхиляється, якщо в ньому забагато percent-encoded послідовностей
  формату `%xx`, наприклад `%D0`, `%AF`, `%20`.

Для `%xx` фільтра зараз використовується простий поріг: щонайменше 8 таких
послідовностей і понад 20% тексту займають ці encoded-послідовності. Це дозволяє
звичайні URL або поодинокі encoded символи, але відсікає тексти, де значна
частина повідомлення схожа на encoded payload.

## HTTP відповіді

Порушення формату тексту повертаються як помилки валідації або `400`:

```json
{
  "detail": "Post contains too many percent-encoded characters."
}
```

Порушення cooldown або кількісних лімітів повертаються як `429 Too Many Requests`.
Якщо можна порахувати коротку паузу до наступної спроби, backend додає header:

```http
Retry-After: 17
```

Тіло відповіді:

```json
{
  "detail": "Please wait before publishing another post."
}
```

## Де налаштовано

Основні параметри описані в:

```text
voidtalk_api/core/antispam.py
```

Перевірка викликається в:

```text
voidtalk_api/services/posts.py
```

Лічильники читаються з таблиці `posts` за `user_id` та `created_at`, тому окрема
таблиця для антиспаму не потрібна.
